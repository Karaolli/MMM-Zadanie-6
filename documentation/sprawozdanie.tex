\section{Przedstawienie problemu}

Celem projektu było opracowanie i zaimplementowanie symuacji (odpowiedzi czasowe) w środowisku Python układu silnika elektrycznego prądu stałego. Sygnałem wejściowym układu jest napięcie (sygnał harmoniczny, prostokątny i trójkątny), które jest podawane na twornik silnika, a sygnałami wyjściowym są prąd płynący w tworniku oraz prędkość obrotowa wału wirnika. Układ składa się z części elektrycznej (obwód twornika) oraz części mechanicznej (wirnik), w części analitycznej zostały wyznaczone wzory dla obu części i połączone ze sobą za pomocą wzorów na moment obrotowy (zależny od prądu) i wsteczną siłę elektromotoryczną (zależną od prędkości wału). Jest to stabilny, co zostało pokazane na końcu części analitycznej, liniowy, stacjonarny układ dynamiczny.

\section{Opis kodu}

Plik \texttt{simulation.py} zawiera kluczowe funkcje do symulowania układu.

\subsection{Model stanowy}
Funkcja \texttt{make\_state\_model()} tworzy macierze modelu stanowego (A, B, C, D) na podstawie parametrów układu (R, L, k itd.).

\begin{lstlisting}
def make_state_model(R, L, K_T, K_e, J, k):
    A = np.array([[ -R/L, -K_e/L,    0],
                  [K_T/J,      0, -k/J],
                  [    0,      1,    0]])
    B = np.array([[1/L],
                  [  0],
                  [  0]])
    C = np.array([[1, 0, 0],
                  [0, 1, 0],
                  [0, 0, 1]])
    D = np.array([[0],
                  [0],
                  [0]])
    return A, B, C, D
\end{lstlisting}

Macierz A jest macierzą stanu, i opisuje zachowanie swobodne, czyli zależące tylko od stanu układu.

Macierz B opisuje to, jak wejście wpływa na stan układu.

*Szczególne postaci macierzy A i B pochodzą z części analitycznej.

Macierz C jest macierzą obserwacji, czyli wybiera wartości których stanów przechodzą na wyjście.
W naszym przypadku jest to macierz jednostkowa, co powoduje że możemy obserwować wszystkie stany układu niezależnie, z wektora \textbf{y}.

Macierz D jest macierzą sprzężenia bezpośredniego i w rzeczywistych układach równa 0, ponieważ inaczej byłaby natychmiast odpowiedź na wejście, co jest fizycznie niemożliwe.

\subsection{Symulacja i całkowanie}
Symulacja układu polega na obliczeniu pochodnych stanów z macierzy A i stanów, oraz macierzy B i wejścia.
Następnie, na podstawie obliczonych pochodnych należy aktualizować stany, całkując pochodne w czasie.
Jedną z metod całkowania, która jest bardziej dokładna niż metoda prostokątów, i przy tym nie jest zbyt skomplikowna w implementacji, jest metoda Rungego-Kutty 4 stopnia.
Jej realizacja odbywa się przez funkcję \texttt{rk4\_step()}.
\begin{lstlisting}
def rk4_step(x, u, dt, A, B, C, D):
    y = C @ x + D * u
    def dxdt(x, u):
        return A @ x + B * u
    k1 = dxdt(x          , u)
    k2 = dxdt(x + k1*dt/2, u)
    k3 = dxdt(x + k2*dt/2, u)
    k4 = dxdt(x + k3*dt  , u)
    x += dt * (k1 + 2*k2 + 2*k3 + k4) / 6
    return x, y
\end{lstlisting}
Z tą metodą, całkowanie z krokiem $dt$ polega na obliczeniu kolejnych wektorów pochodnych: k1 w czasie $t_0$, k2 i k3 w czasie $t_0$ + $dt \over 2$, oraz k4 w czasie $t_0$ + $dt$.
Zakładamy, że wejście $u$ pozostaje stałe w czasie jednego kroku.

Na końcu, wektor stanu zmienia się o średnią ważoną tych wektorów pochodnych.

Wyjście \textbf{y} układu jest obliczane na początku funkcji, ponieważ ma ono odbywać się ze stanem przed aktualizacją.

Wzory \texttt{dxdt = A @ x + B * u} oraz \texttt{y = C @ x + D * u} (gdzie \texttt{@} oznacza mnożenie macierzowe) oczywiście pochodzą z postaci równań modelu stanowego.
Wejście $u$ jest skalarem, dlatego można użyć mnożenie skalarne zamiast macierzowego.

Funkcja zwraca zmodyfikowany wektor stanu \textbf{x} oraz wektor wyjścia \textbf{y}.

\section{Wnioski}
Udało się stworzyć model matematyczny (stanowy) danego układu, oraz zasymulować go odpowiedzi na różne sygnały wejściowe, z wykreśleniem przebiegów każdego ze stanów. Program umożliwia również zmianę parametrów układu, kroku symulacji, oraz warunków początkowych.

Algorytm całkowania Rungego-Kutty powinien być dość precyzyjny, jednak dla dużych kroków symulacji można zauważyć zniekształcenia.
Szczególnie, oscylacje zanikają, a dla niektórych kombinacji parametrów, wartości mogą wybuchnąć do nieskończoności, mimo tego, że teoretycznie układ powinien być stabilny.
Wynika to z tego, że najszybsza stała czasowa jest zbyt szybka dla użytej metody całkowania przy tym kroku symulacji.
